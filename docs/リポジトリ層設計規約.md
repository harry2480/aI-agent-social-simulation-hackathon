# SLEEP CITY 2.0 Repository レイヤー設計方針

データベース（Supabase PostgreSQL / Prisma）への直接アクセスは
`apps/webapp/src/backend/infrastructure/repositories/` に集約します。
Repository の interface は `apps/webapp/src/backend/domain/repositories/` に置き、
loaders / actions / UseCase からは必ず interface 越しに Repository を呼び出してデータを操作します。

Simulation Engine（domain/services）は Repository を直接呼びません。
Tick 処理の結果はメモリ上に蓄積し、UseCase が Run 単位・バッチ単位で永続化します。
これは 300 Agent × 7 日（672 Tick）の実行で書き込みがボトルネックになるのを避けるためです。

## 基本パターン

```typescript
// apps/webapp/src/backend/domain/repositories/simulation-run.repository.ts
import type { SimulationRun } from '../models/simulation-run.model';

export interface SimulationRunRepository {
	save(run: SimulationRun): Promise<void>;
	findById(id: string): Promise<SimulationRun | null>;
	findByExperimentId(experimentId: string): Promise<SimulationRun[]>;
}
```

```typescript
// apps/webapp/src/backend/infrastructure/repositories/prisma-simulation-run.repository.ts
import { SimulationRun } from '../../domain/models/simulation-run.model';
import type { SimulationRunRepository } from '../../domain/repositories/simulation-run.repository';
import { prisma } from '../db/prisma-client';

export class PrismaSimulationRunRepository implements SimulationRunRepository {
	async save(run: SimulationRun): Promise<void> {
		await prisma.simulationRun.create({
			data: {
				id: run.id,
				experimentId: run.experimentId,
				seed: run.seed,
				population: run.population,
				days: run.days,
				intervention: run.intervention,
				aiModel: run.aiModel,
				status: run.status,
				createdAt: run.createdAt,
			},
		});
	}

	async findById(id: string): Promise<SimulationRun | null> {
		const record = await prisma.simulationRun.findUnique({ where: { id } });
		if (record === null) {
			return null;
		}

		return SimulationRun.reconstruct({
			id: record.id,
			experimentId: record.experimentId,
			seed: record.seed,
			population: record.population,
			days: record.days,
			intervention: record.intervention,
			aiModel: record.aiModel,
			status: record.status,
			createdAt: record.createdAt,
		});
	}
}
```

## 実装ルール

- **interface は domain、実装は infrastructure に置く。** application 層は interface のみに依存する
- **Prisma Client の生成は `infrastructure/db/prisma-client.ts` に閉じ込める。** UseCase・loader・action・domain から直接 import しない
- Repository は Prisma のレコードを必ずドメインモデルへ変換して返す。Prisma の型を層の外へ漏らさない
  - 再構築には `Model.reconstruct()` を使い、`Model.create()`（新規生成時の検証・ID 採番を伴う）と区別する
- Repository 関数は「DB クエリ実行 + 第一レイヤーのエラーハンドリング」のみを担当し、
  **複雑なビジネスロジックは呼び出し元（UseCase・domain service）に残す**
  - 例外として、Experiment 結果の集計（Cascade Probability・Average Rs・標準偏差など Run 横断の集計）は
    SQL 側で実行したほうが効率的なため Repository に実装してよい
  - キャッシュ制御や DTO 変換はアプリケーション層以上で行う
- Infrastructure 層のエラーは throw する（domain 層のみ `Result<T, E>` を使う）

## SLEEP CITY 固有の Repository 一覧

| interface | 実装 | 主な対象テーブル |
|---|---|---|
| `ExperimentRepository` | `prisma-experiment.repository.ts` | `experiments`, `experiment_results` |
| `SimulationRunRepository` | `prisma-simulation-run.repository.ts` | `simulation_runs` |
| `AgentRepository` | `prisma-agent.repository.ts` | `agents`, `agent_relationships` |
| `EventRepository` | `prisma-event.repository.ts` | `events`, `causal_edges` |
| `AgentDecisionRepository` | `prisma-agent-decision.repository.ts` | `agent_decisions` |
| `MetricsRepository` | `prisma-metrics.repository.ts` | `metrics` |

## 書き込み量とパフォーマンスの規約

- **Tick ごとの全 Agent 状態は保存しない。** 保存対象は重要 Event、Causal Edge、集計 Metrics、AI Decision に限る
- Event / Causal Edge の保存は `createMany` によるバルク Insert を使う。1 件ずつの `create` をループで呼ばない
- Run 単位の保存は Prisma のトランザクションで囲み、Event だけ保存され Metrics が欠ける中途半端な状態を作らない
- Batch Experiment で多数 Run を並列実行する場合、Prisma Client のコネクション上限に注意し、
  同時実行数を UseCase 側で制御する
- Metrics は Tick 単位ではなくサンプリング間隔（例: 1 時間 = 4 Tick ごと）で保存し、時系列グラフに必要な粒度に留める

## 削除・再実行

- Experiment の再実行時は、対象 Experiment に紐づく Run・Event・Metrics をカスケード削除できるように
  外部キー制約を設定する（`experiments` → `simulation_runs` → `events` / `metrics`）
- Integration テストのクリーンアップも同じカスケード経路を利用する
