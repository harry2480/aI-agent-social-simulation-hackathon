# SLEEP CITY 2.0 Web フロントエンド実装方針

## 1. 概要

SLEEP CITY 2.0 の Web フロントエンドの実装方針と要件定義を定めます。
バックエンドの DDD 4 層（`src/backend/`）に対し、フロントエンドは **feature 単位のディレクトリ分割**を採用し、
`src/backend/presentation/`（loaders / actions）のみを接続点として保守性と拡張性の高いコードベースを構築します。

主要画面は Simulation / Experiment / Critical Point / Super-spreader / Settings の 5 つです。

## 2. 技術スタック

### コア技術
- **Framework**: Next.js 15 (App Router)
- **Language**: TypeScript
- **Styling**: Tailwind CSS v4
- **State Management**: Zustand（Simulation の再生速度・選択中 Agent・表示フィルタなどのクライアント状態のみ）
- **Data Fetching**: Server Components + loaders。進行中 Simulation の更新は Server Actions のポーリング / Streaming
- **Database Client**: Prisma（backend 層のみ。フロントエンドからは参照しない）
- **Form Management**: React Hook Form + Zod（Experiment Config フォーム）
- **UI Components**: shadcn/ui（Radix UI ベース）

### 可視化
- **Causal Graph**: React Flow
- **KPI 時系列グラフ**: Recharts
- **City Map**: Canvas（300〜500 Agent の高頻度描画のため DOM ではなく Canvas を既定とする。低 Zoom 時はエリア単位で集約表示）

### 開発ツール
- **Linter/Formatter**: Biome
- **Testing**: Vitest
- **E2E Testing**: Playwright（P2）

## 4. 機能要件

### Phase 1: MVP（P0）

#### 4.1 City Map と Agent 表示
- **要件**:
  - Home / Workplace / Store / Logistics Hub / Road と Agent を地図上に表示
  - 睡眠状態（Normal / Tired / Sleep Deprived / Severe Sleep Deprived）を色で視覚的に区別
  - Traffic Congestion / Accident / Sleep Transmission をオーバーレイ表示
  - レスポンシブデザイン対応（デモは PC 前提だが、パネル折りたたみでタブレット幅まで対応）
- **表示項目**:
  - Agent マーカー（Role アイコン + 睡眠状態カラー）
  - 施設・道路・混雑度
- **機能（初期スコープ）**:
  - Zoom / Pan: あり。低 Zoom 時はエリア単位で集約表示
  - フィルタ: 職種別・睡眠状態別の表示切り替え

#### 4.2 KPI パネル
- **要件**:
  - Current Rs / Peak Rs / Average Rs、Sleep-Deprived Population、Total Sleep Debt、Cascade Reach 等をリアルタイム更新
  - Rs は疫学上の R0 ではない旨の注記を UI 上に常設

#### 4.3 Event Timeline
- **要件**:
  - 重要 Event のみを時系列表示（全 Tick ログは表示しない）
  - Event クリックで対象 Agent を City Map 上でハイライト

#### 4.4 Agent Detail
- **要件**:
  - Agent クリックで Role / 現在地 / 現在行動 / Sleep Debt / Fatigue / Stress / 性格パラメータを表示
  - Last AI Decision・Decision Reason・使用 AI Model を表示
  - Parent Transmission / Child Transmissions から因果を辿れる

### Phase 2: 機能拡張（P1 以降）
- Causal Graph UI（React Flow によるノードクリック詳細表示）
- Experiment Dashboard（条件比較・分散表示）
- Critical Point Explorer（Sweep 結果の Cascade Probability 曲線）
- Sleep Super-spreader Explorer（ランキング表示）
- Simulation Replay（P2）

## 5. 非機能要件

### パフォーマンス
- First Contentful Paint (FCP): < 1.5 秒
- Time to Interactive (TTI): < 3 秒
- Cumulative Layout Shift (CLS): < 0.1
- Watch Mode 8x 実行時も UI 操作を阻害しない（City Map は Canvas + requestAnimationFrame でバッチ描画）
- Experiment Mode では描画を完全に停止する
- Event Timeline は仮想スクロールで表示件数を制限する

### アクセシビリティ
- WCAG 2.1 Level AA 準拠
- キーボードナビゲーション対応（再生 / 一時停止 / 速度変更）
- スクリーンリーダー対応
- 適切な ARIA 属性の使用
- **睡眠状態は色だけで区別しない**。アイコン形状・ラベルを併用する（色覚特性への配慮）

### SEO
- 発表・共有用のトップページとプロジェクト説明ページのみ対象
- 適切なメタタグ設定と OGP 対応（Cascade 可視化のサムネイル）
- Simulation の実行結果ページは動的コンテンツのため index 対象外とする

## 6. 実装ガイドライン

### コーディング規約
1. **コンポーネント設計**
   - 単一責任の原則
   - Props Interface の明確な定義
   - 描画コンポーネントと状態管理を分離し、City Map は「状態を受け取って描くだけ」に保つ
2. **型定義**
   - 全てのコンポーネントで TypeScript を使用
   - any 型の使用禁止
   - Agent / Event / Metrics の型は backend/presentation が返す型を単一の情報源として再利用する
3. **スタイリング**
   - Tailwind CSS のユーティリティファースト
   - カスタムコンポーネントでの `cn()` ヘルパー使用
   - 睡眠状態の色は必ずカラートークン経由（`docs/スタイルガイド.md` 参照）

### アーキテクチャ原則
1. **Feature-based 構造**: 機能ごとにモジュール化（city-map / kpi / timeline / causal-graph / experiment）
2. **明確な責任分離**: Components、Hooks、Stores、Lib の分離
3. **依存関係の管理**: 循環参照を避ける。フロントエンドから `src/backend/` は presentation 層のみ参照可（dependency-cruiser で強制）
4. **テスタビリティ**: 色マッピング・集約ロジック・フォーマッタは純粋関数として切り出す

## 7. 実装順序

1. **基盤構築**
   - shadcn/ui セットアップ、カラートークン定義、ダッシュボードレイアウト実装
2. **Simulation 画面実装**
   - City Map → KPI パネル → Event Timeline → Agent Detail の順に実装
3. **Experiment 系画面実装**
   - Experiment Dashboard → Critical Point Explorer → Super-spreader Explorer
4. **Causal Graph 実装**
   - React Flow によるノード・エッジ描画と詳細パネル連携

## 8. テスト戦略

### ユニットテスト
- 色マッピング・集約表示ロジック・数値フォーマッタなどの純粋関数
- カスタムフック（再生速度制御など）

### 統合テスト
- loaders 経由のデータ取得とページコンポーネントの結線
- Server Actions による Simulation 作成フロー

### E2E テスト（対象スコープ）
- Simulation 作成 → 実行 → City Map で状態変化を確認するクリティカルパス
- Experiment Config フォームの送信

- **CI/CD**: GitHub Actions（`pnpm verify`）+ Vercel
- **プレビュー環境**: PR ごとの自動デプロイ
