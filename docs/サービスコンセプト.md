# SLEEP CITY 2.0 - サービスドキュメント

## サービス概要
SLEEP CITY 2.0 は、都市の中で睡眠不足が他者へ伝播し自己増殖していく現象（Sleep Cascade）を分かりやすく可視化し、
研究者・開発者・発表オーディエンスの「睡眠不足の社会的伝播に対する理解と発見」を促進するプラットフォームです。
AI マルチエージェントシミュレーションを活用した詳細分析と、City Map・Causal Graph・Event Timeline を組み合わせた
直感的なダッシュボード型 UI で、都市規模の睡眠不足連鎖をもっと身近に、もっと理解しやすくします。

本システムは現実都市を正確に予測するものではなく、
**睡眠不足の都市内伝播という仮説を検証するための仮想実験環境**として位置付けます。

## コンセプト

### 1. 実験基盤としての Simulation Engine
**目的**: 研究者・開発者の仮説検証と再現可能な実験の実施を支援

**機能**:
- 300 Agent × 7 日間（最大 500 Agent × 14 日間）の都市シミュレーション実行
- 6 職種（Office Worker / Manager / Driver / Delivery Worker / Store Worker / Parent 属性）の AI エージェントによる意思決定
- Seed 固定による再現性の担保と、条件を 1 つだけ変えた公平な比較実験

### 2. 因果を追える可視化・情報提供
**目的**: 「なぜその人が寝不足になったのか」を誰でも追跡でき、結果の説得力を高める

**特徴**:
- City Map 上で Agent の睡眠状態（Normal / Tired / Sleep Deprived / Severe）と Cascade 拡大をリアルタイム表示
- Event Timeline で重要イベントのみを時系列で提示（全 Tick ログは表示しない）
- Causal Graph で Patient Zero から New Sleep-Deprived Case までの因果経路をノード単位で辿れる

**参考事例**: 感染症の実効再生産数ダッシュボード
- 時系列で再生産数と新規ケース数を並べて提示する構成
- ただし Rs は疫学上の R0 そのものではないことを UI・発表資料で明示する

### 3. 実験条件の比較と探索機能
**目的**: 単一 Run の印象論ではなく、複数条件・複数 Seed の定量結果から発見を導く

**主要機能**:
- **Experiment Dashboard**
  - Baseline / Random Shock / Driver Shock / Manager Shock / Intervention の比較
  - Average Rs・Peak Rs・Cascade Probability・Total Sleep Loss を分散付きで表示

- **Critical Point Explorer**
  - 初期睡眠不足率（1%〜20%）を自動 Sweep し、各条件を複数 Seed で実行
  - Cascade Probability が 50% を超える周辺を臨界点候補として提示

- **Sleep Super-spreader Explorer**
  - Stage 1 で Rule-based 高速 Simulation により全 Agent を Patient Zero 候補として評価
  - Stage 2 で上位 10〜20 Agent を AI Decision 有効・複数 Seed で再検証

### 4. 介入施策の評価・副作用分析機能
**目的**: 「どこへ介入すれば Cascade を止められるか」の定量化と、想定外の副作用の可視化

**対象と機能**:
- **Mandatory Rest / Overtime Limit**
  - Driver の Fatigue 閾値超過時の強制休憩、最大残業時間の制限
  - Rs・Cascade Probability・Accident Count への効果を測定

- **Flexible Work / Remote Work**
  - 遅刻分の残業補填を緩和、一部 Office Worker の通勤を削除
  - Transportation Network の負荷変化と Household Network への波及を測定

- **副作用分析**
  - 介入別・職種別・Network 別のフィルタリング
  - 「ある Network では改善するが別 Network を通じて逆効果になる」ケースのクロス分析

## 期待される効果
1. **臨界点の発見** - 初期睡眠不足率のどこに Cascade が自己増殖し始める領域があるかを定量的に提示できる
2. **Super-spreader の特定** - 職種だけでなく、複数 Network の境界に位置する Agent の伝播力を明らかにできる
3. **介入設計への示唆** - Rs を 1 未満へ抑える介入と、逆効果を生む介入を区別して提示できる
4. **説明可能な創発の提示** - AI Agent の意思決定と確率イベントを区別したうえで、都市レベルの創発現象を因果経路付きで説明できる

## 技術スタック（想定）
- フロントエンド: Next.js 15 (App Router) + TypeScript + Tailwind CSS + shadcn/ui + Zustand
- バックエンド: Next.js Server Actions / Server Components 上の DDD 4 層（Simulation Engine は domain 層）
- インフラ/DB: Vercel + Supabase (PostgreSQL) + Prisma
- 外部連携/AI: OpenRouter API（Gemma 系 Instruction Model、Structured Output、Decision Cache、Rule-based Fallback）
- 可視化: React Flow（Causal Graph）+ Recharts（KPI 時系列）+ Canvas / SVG（City Map）
