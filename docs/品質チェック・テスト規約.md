# SLEEP CITY 2.0 品質チェック規約

`vitest` + `TypeScript` + `dependency-cruiser` + `Biome` によるコード品質チェック規約。

---

## Quality Check 一覧

| チェック | ツール | 対象 | コマンド |
|---|---|---|---|
| Unit テスト | vitest | domain（Simulation Engine）, application（UseCase） | `pnpm test:unit` |
| Integration テスト | vitest | infrastructure（Prisma Repository, OpenRouter Adapter） | `pnpm test:integration` |
| カバレッジ計測 | vitest + v8 | `test/unit` | `pnpm test:coverage` |
| 型チェック | `tsc --noEmit` | 全ソース | `pnpm typecheck` |
| 依存方向チェック | dependency-cruiser | `apps/webapp/src` | `pnpm depcruise` |
| リンター / フォーマッター | Biome | 全ソース | `pnpm lint` / `pnpm lint:fix` |
| 未使用コード検出 | knip | 全ソース | `pnpm knip` |

### verify コマンド 実行フロー

`pnpm verify` は以下の順序で実行される：

1. lint（Biome）
2. prisma generate（Prisma Client の型生成）
3. typecheck
4. unit test
5. depcruise

コード変更後は必ず実行し、全パスすることを確認する。
CI（`.github/workflows/verify.yml`）でも同じコマンドが実行される。
また `pre-commit` で `pnpm lint:fix`、`pre-push` で `pnpm verify` が simple-git-hooks により自動実行される。

## 型チェック (TypeCheck)

- `tsc --noEmit` で型エラーがないことを確認する
- **`any`** の使用は原則禁止（一時的な回避には lint 抑制コメントを明確に併記する）
- OpenRouter からの AI レスポンスは `unknown` として受け取り、Structured Output のスキーマ検証を通してから型付けする。
  検証を通さないキャストは禁止
- CI で必ず実行。型エラーがある PR はマージ不可とする

## 依存方向チェック (Dependency Cruise)

- `docs/アーキテクチャ.md` で定義された依存方向（presentation → application → domain ← infrastructure）を機械的にチェックする
- 設定ファイル: `apps/webapp/.dependency-cruiser.cjs`
- 検出されるルール:
  - `domain` から `application` / `infrastructure` / `presentation` への依存禁止
  - `application` から `infrastructure` への直接依存禁止（Gateway interface 経由のみ）
  - `presentation/loaders`, `presentation/actions` から `domain` / `infrastructure` への直接依存禁止
  - `src/app/`, `src/frontend/` から `src/backend/presentation/` 以外への依存禁止
- 違反があった場合、モジュールの切り出し・配置を見直す。ルール側を緩めて解決しない

## Simulation 固有の品質基準

Simulation Engine は結果の信頼性が作品価値に直結するため、通常のテストに加えて以下を満たすこと。

### 再現性
- 同一 Seed・同一 Experiment Config で 2 回実行し、KPI と Event 列が一致することを Unit テストで検証する
- domain 層での `Math.random()` / `Date.now()` の使用は禁止。乱数は `SeededRandomService`、時刻は Simulation Clock から取得する
- AI Decision を含む Run は非決定になり得るため、再現性検証は Rule-based Adapter または Decision Cache 有効時に行う

### 完走性
- 300 Agent × 7 日間の Simulation が例外なく完走することを、リリース前に手動または長時間ジョブで確認する
- OpenRouter API が失敗しても Rule-based Fallback により Run が停止しないことを Integration テストで検証する
- イベント伝播は `MAX_EVENT_DEPTH = 10` で打ち切られ、同一 Tick 内で無限連鎖しないことを Unit テストで検証する

### 数値の妥当性
- Agent 属性の範囲（fatigue / stress: 0〜100、その他の性格パラメータ: 0〜1）を逸脱しないことをモデル側で強制し、テストする
- Rs・Cascade Reach・Sleep Debt が負値や NaN にならないことを境界値テストで確認する

---

## カバレッジ方針

- domain 層（Simulation Engine・Sleep / Fatigue・Rs・Cascade 判定）は重点的にテストを書く
- 数値計算・判定ロジックは境界値を必ずケース化する
- UI コンポーネントの見た目そのものはカバレッジ対象としない。純粋関数として切り出したロジックのみ対象とする
