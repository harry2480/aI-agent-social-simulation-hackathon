# SLEEP CITY 2.0 アーキテクチャ設計規約

pnpm workspace + Next.js 16 App Router における DDD バックエンド設計規約。
`apps/webapp/src/backend/` 配下に適用する。

Simulation Engine（Tick 処理・Sleep / Fatigue 計算・確率イベント・Rs 算出）はすべて domain 層に置き、
OpenRouter などの外部依存を持たない純粋なロジックとして実装する。これにより Seed 固定時の再現性と
Unit テスト可能性を担保する。

---

## ディレクトリ構成

```text
apps/webapp/src/backend/
├── domain/
│   ├── models/          # ドメインモデル（Agent, City, SimulationEvent, SleepDebt, Rs 等）
│   ├── services/        # ドメインサービス（Simulation Engine, Cascade 判定等）
│   ├── gateways/        # Gateway interface（AI Decision Gateway 等）
│   └── repositories/    # Repository interface
├── application/
│   └── usecases/        # ユースケースオーケストレーション（Simulation 実行・Experiment 実行）
├── infrastructure/
│   ├── adapters/        # Gateway 実装（OpenRouter Adapter, Rule-based Stub Adapter）
│   ├── repositories/    # Repository 実装（Prisma）

    ├── loaders/         # データ取得（読み取り専用）

```

## DDD 4 層構造

| 層 | ディレクトリ | 責務 |
|---|---|---|
| presentation | `presentation/composition/` `loaders/` `actions/` | Next.js Server Components / Server Actions との接続。Simulation の起動・進行・結果取得 |
| application | `application/usecases/` | ユースケースオーケストレーション。プロンプト生成・レスポンスパース・Fallback 判断・Decision Cache 制御を含む |
| domain | `domain/models/` `services/` `gateways/` `repositories/` | Simulation Engine 本体。ビジネスルール。外部依存なし |
| infrastructure | `infrastructure/adapters/` `repositories/` `db/` | OpenRouter 接続・Prisma 永続化。Gateway / Repository 実装 |

---

## 依存方向（厳守）

`presentation → application → domain ← infrastructure`

- **domain は最内層。** 他層への依存禁止
- **application は domain にのみ依存。** infrastructure への直接依存禁止（Gateway interface 経由）
- **infrastructure は domain/gateways, domain/repositories に依存。** interface を implements する
- **presentation/loaders, actions は application + presentation/composition にのみ依存。** domain・infrastructure の直接参照禁止
- **presentation/composition は全層を参照可。** UseCase と infrastructure 実装を組み立てる唯一の場所
- **フロントエンド** (`src/app/`, `src/frontend/`) **は backend/presentation/ にのみ依存**

これらは `apps/webapp/.dependency-cruiser.cjs` で機械的に検証され、`pnpm verify` の depcruise ステップで CI に組み込まれる。

## presentation 層: composition / loaders / actions

Next.js と DDD の唯一の接続点。**API Route は原則使用しない。**
ただし要件定義 41 章で定義した外部連携用エンドポイント（`POST /api/simulations` 等、
Batch Experiment Runner や外部スクリプトからの呼び出し）に限り API Route を許可する。
その場合も Route Handler は composition から UseCase を取得して呼ぶだけとし、ロジックを持たせない。

| 種別 | 責務 | 呼び出し元 |
|---|---|---|
| composition | UseCase + infrastructure 実装の組み立て（Composition Root） | loader, action, route handler |
| loader | データ取得（Simulation 状態、Event、KPI、Experiment 結果） | Server Component (`page.tsx`) |
| action | 副作用（Simulation 作成・実行・停止、Experiment 投入） | Server Actions (`'use server'`) |

- **page.tsx は loader を呼んで props を渡すだけ。** ロジック禁止
- **loader / action は composition から UseCase を取得して呼ぶ。** infrastructure の直接 import 禁止
- **composition は全層を参照してよい唯一の場所。** UseCase に infrastructure 実装を注入し、エクスポートする

## ドメインモデル設計

**Rich Domain Model を徹底する。Anemic Domain Model 禁止。**

- 値の生成・検証・変換はモデル自身のファクトリメソッド / インスタンスメソッドで行う
  - 例: `Agent.create()` で Seed 付き乱数から sleepNeed / 性格パラメータを生成し、範囲を検証する
  - 例: `SleepDebt.applyDailyDeficit()` / `recover()` は SleepDebt モデル自身のメソッドとする
  - 例: 睡眠状態（Normal / Tired / Sleep Deprived / Severe）の判定は `SleepState.from(sleepDebt, thresholds)` に閉じる
- ドメイン不変条件はファクトリメソッド / コンストラクタで強制する。不正な状態のオブジェクト生成を許さない
  - fatigue / stress は 0〜100、responsibility / riskTolerance / cooperativeness / workPressure / familyResponsibility は 0〜1 に収める
  - `SimulationEvent` は `causedByEventIds` の参照整合と伝播 Depth 上限（`MAX_EVENT_DEPTH = 10`）を生成時に検証する
- domain service に置くのは「複数モデルの協調」のみ。単一モデルで完結するロジックをサービスに書かない
  - Sleep Transmission 判定や Rs 算出は複数 Agent と Event を横断するため domain service に置く
  - 個々の Agent の Sleep Debt 加算は Agent / SleepDebt モデルに置く

## サービス実装規約

**全サービス（domain service, UseCase）はクラスベース + コンストラクタ DI。関数エクスポートによるサービス実装は禁止。**

- コンストラクタの `private readonly` パラメータで Gateway 等の依存を受け取る
- ビジネスロジックは `execute()` 等の public メソッドで公開する
- ヘルパーは private メソッドに閉じる。クラス外への export 禁止
- 乱数は必ず `SeededRandomService` をコンストラクタで受け取る。`Math.random()` の直接使用は禁止（再現性が壊れるため）
- 現在時刻は Simulation Clock（Tick）から取得する。domain 層での `Date.now()` 使用は禁止

例外: 型定義 (`interface`, `type`) およびユーティリティ型 (`Result<T, E>` 等) は関数 / 定数エクスポート可。
Simulation Parameter の定数（`MAX_EVENT_DEPTH` 等）も domain/models 配下での定数エクスポートを可とする。

## Gateway / Repository パターン

| 種類 | interface 配置 | 実装配置 |
|---|---|---|
| Gateway | `domain/gateways/` | `infrastructure/adapters/` |
| Repository | `domain/repositories/` | `infrastructure/repositories/` |

SLEEP CITY での主な実装対応:

| interface | 本番実装 | Stub / Fallback 実装 |
|---|---|---|
| `AiDecisionGateway` | `openrouter-ai-decision.adapter.ts` | `rule-based-ai-decision.adapter.ts` |
| `SimulationRunRepository` | `prisma-simulation-run.repository.ts` | — |
| `EventRepository` | `prisma-event.repository.ts` | — |
| `ExperimentRepository` | `prisma-experiment.repository.ts` | — |

- 外部 API の Gateway は必ず Stub 実装を用意し、composition で環境変数に応じて切り替える
- `OPENROUTER_API_KEY` 未設定時、および Experiment Mode（大量 Batch 実行）では Rule-based 実装を注入する
- OpenRouter 呼び出し失敗・Structured Output 形式不正時は adapter 内でリトライせず、UseCase が Rule-based Fallback へ切り替える
