# SLEEP CITY 2.0 インフラ規約

pnpm workspace + Vercel + Supabase(PostgreSQL) + Prisma によるインフラ環境の構成と規約。

---

## Monorepo 構成

pnpm workspace で管理。`apps/` 配下に各アプリケーションを配置する。

```text
sleep-city/
├── apps/
│   └── webapp/          # Next.js 15 (App Router) アプリ
│       ├── prisma/      # schema.prisma / migrations / seed
│       ├── src/         # backend(DDD 4層) + app + frontend
│       └── test/        # unit / integration
├── supabase/            # supabase config.toml（ローカルスタック設定）
├── docs/                # 要件定義・設計ドキュメント
├── pnpm-workspace.yaml
├── biome.json           # 共有 lint/format 設定
├── knip.json            # 未使用コード検出設定
└── package.json         # workspace scripts
```

`pnpm-workspace.yaml` は `apps/*` のみを対象とする。共通パッケージを切り出す場合は `packages/*` を追加する。

## デプロイメント

| 環境 | トリガー | プラットフォーム | 備考 |
|---|---|---|---|
| Preview | PR 作成 / 更新 | Vercel（自動プレビュー、PR ごとに一意の URL） | Preview 用 Supabase プロジェクトへ接続。Simulation は縮小 Population で動作確認する |
| Production | main ブランチへの push | Vercel（自動本番デプロイ） | 発表・デモ用。Watch Mode の描画性能を優先する |

開発は `develop` ブランチを起点にフィーチャーブランチを切り、PR 経由で `main` へマージする。

### Vercel 設定

- Framework Preset: Next.js
- Node.js Version: 22.x
- Build Command: `pnpm build`（内部で `prisma generate && next build`）
- Install Command: `pnpm install`
- 本番マイグレーション適用時は `pnpm --filter webapp build:vercel`（`prisma migrate deploy` を含む）を使用する
- Function 実行時間の上限に注意する。300 Agent × 7 日の Batch Experiment は Vercel Function 上で完走させず、
  ローカルまたは長時間実行可能なワーカーで実行し、結果のみ DB に保存する

### 環境変数

| 変数 | 用途 | 設定先 |
|---|---|---|
| `DATABASE_URL` | Prisma 接続（Connection Pooling 経由） | Vercel / ローカル `.env` |
| `DIRECT_URL` | マイグレーション用の直接接続 | Vercel / ローカル `.env` |
| `OPENROUTER_API_KEY` | OpenRouter API キー | Vercel / ローカル `.env` |
| `AI_MODEL` | 使用モデル ID（例: `google/gemma-3-27b-it`） | Vercel / ローカル `.env` |
| `INTEGRATION_TEST` | Integration テスト有効化フラグ | ローカル / CI |

- モデル ID をソースコードへ直接固定しない。必ず `AI_MODEL` から読む
- `OPENROUTER_API_KEY` 未設定時は Rule-based Adapter へ自動フォールバックする（composition で分岐）
- API キーはクライアントへ露出させない。`NEXT_PUBLIC_` プレフィックスを付けない

## Supabase / PostgreSQL 環境

- **スキーマ管理**: Prisma を単一の情報源とする。`pnpm db:migrate` でマイグレーション作成・適用、`pnpm db:reset` で初期化
- **シード**: `pnpm db:seed`（`apps/webapp/prisma/seed.ts`）。都市モデルの雛形や検証用 Experiment Config を投入する
- **環境変数**: Preview 環境と Production 環境で別々の Supabase プロジェクト（API Key / URL）を紐付ける
- **ローカル開発**: `pnpm supabase start` でローカルスタックを起動し、`DATABASE_URL` をローカルに向ける
- **書き込み量の抑制**: Simulation 中の全 Tick 状態は保存しない。重要 Event・Causal Edge・集計 Metrics のみ永続化する
- **Batch Experiment**: 多数 Run を並列実行するとコネクションが枯渇するため、Prisma Client はプロセス内でシングルトン
  （`infrastructure/db/prisma-client.ts`）を共有し、Run 単位の書き込みはバルク Insert にまとめる

## CI

`.github/workflows/verify.yml` が PR / push で `pnpm verify`（lint → prisma generate → typecheck → unit test → depcruise）を実行する。
Integration テストは `DATABASE_URL` と `INTEGRATION_TEST=true` が設定された環境でのみ実行され、未設定時はスキップされる。
