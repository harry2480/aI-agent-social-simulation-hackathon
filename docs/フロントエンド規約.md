# SLEEP CITY 2.0 フロントエンド規約

Next.js 16 App Router + shadcn/ui + Tailwind CSS におけるフロントエンド規約。

---

## ディレクトリ構成

`apps/webapp/src/` 配下:

| ディレクトリ | 責務 |
|---|---|
| `app/` | ページ。Server Component で loader を呼びデータ取得 |
| `frontend/components/` | React コンポーネント。`'use client'` でクライアントを明示 |
| `frontend/components/ui/` | shadcn/ui コンポーネント |
| `frontend/hooks/` | カスタム hooks（再生制御、Tick 購読など） |
| `frontend/stores/` | Zustand ストア（クライアント状態のみ） |
| `frontend/lib/` | クライアント側 util（色マッピング、フォーマッタ） |
| `lib/` | 共通 util（`cn()` など） |
| `backend/` | サーバーサイド構造（`docs/アーキテクチャ.md` 参照） |

---

## Server Components / Client Components の使い分け

- **デフォルトは Server Component。** `'use client'` は必要な場合のみ付与
- Client Component が必要なケース:
  - City Map の Canvas 描画（`ref` / `requestAnimationFrame` / Web API 依存）
  - Simulation の再生・一時停止・速度切り替え（1x / 4x / 8x）などのユーザーインタラクション
  - React Flow による Causal Graph、Recharts によるチャートの操作
  - Experiment Config フォーム（React Hook Form）
- **初期データは必ず Server Component** (`page.tsx` + loader) で取得する。
  実行中 Simulation の逐次更新のみクライアント側で購読する

---

## データフローと状態管理

- **状態管理**: Zustand は最小限のクライアントステートのみに使用する。
  対象は「再生速度」「一時停止状態」「選択中 Agent ID」「City Map の表示フィルタ / Zoom」など UI 状態に限る。
  **Simulation の真の状態（Agent・Event・KPI）を Zustand に二重管理しない**
- **データフェッチ**: Server Components（loader）で取得し Props として降ろす。
  進行中 Run の更新はポーリング間隔を Watch Mode の速度に合わせて調整し、Experiment Mode では停止する
- **ミューテーション**: Server Actions を使用してサーバー側で直接処理する。
  Simulation 作成 / 実行 / 停止、Experiment 投入は `backend/presentation/actions/` の action を呼ぶ
- **backend への依存**: フロントエンドが import してよいのは `src/backend/presentation/` 配下のみ。
  domain / application / infrastructure の直接 import は dependency-cruiser で禁止されている

---

## 大量データ描画の規約

- 300〜500 Agent のマーカーを個別 DOM 要素で描画しない。City Map は Canvas に統一する
- Event Timeline は重要 Event のみを表示し、リストは仮想スクロールで件数を制限する
- Tick ごとの再レンダリングを抑えるため、KPI・Map・Timeline は独立したコンポーネントに分割し、
  更新対象のみ再描画されるようにする
- 睡眠状態の色は `frontend/lib/` の単一マッピング関数から取得し、コンポーネント側で色リテラルを書かない
