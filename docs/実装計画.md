# AI Agent Decision 機能 実装計画書

要件定義書「SLEEP CITY 2.0」12〜17 章（AI Agent 設計 / AI Provider / AI Decision API /
System Prompt / 呼び出し最適化 / Fallback）に基づき、OpenRouter を用いた Agent 意思決定機能の実装手順を示す。
開発計画上は Day 5 に相当し、Day 4 までに完成している Event Engine / Causal Edge / Rs を前提とする。

**スコープ**: AI は Agent の意味的な意思決定のみを担当する。事故発生・移動時間・渋滞計算・Sleep Debt・
Fatigue 計算・確率計算は Simulation Engine（domain 層）の責務であり、本計画の対象外とする。

## 1. 実装フェーズ

### Phase 1: 環境構築とパッケージインストール
- Vercel AI SDK 関連パッケージのインストール
- OpenAI 互換 provider（OpenRouter 用）のセットアップ
- Structured Output 用スキーマ定義ライブラリ（zod）の導入
- OpenRouter API キーとモデル ID の環境変数設定

### Phase 2: Gateway / Adapter 実装
- `AiDecisionGateway` interface の定義（domain 層）
- OpenRouter Adapter の実装（infrastructure 層）
- Structured Output によるレスポンス検証
- Rule-based Fallback Adapter の実装
- Composition での環境変数による切り替え

### Phase 3: Decision Trigger と Cache 実装
- Decision Trigger 判定ロジック（Simulation Engine 側）
- Decision Context の正規化（Fatigue / Delay のビニング）
- Decision Cache の実装
- Decision 結果の永続化（`agent_decisions`）

### Phase 4: 統合とテスト
- Simulation Engine への組み込み
- Agent Detail 画面での Last AI Decision / Decision Reason / AI Model 表示
- API 障害時に Simulation が完走することの検証
- Rule-based Run との結果比較・動作確認

## 2. 詳細実装計画

### 2.1 パッケージインストール

```bash
# apps/webapp で実行
pnpm --filter webapp add ai @ai-sdk/openai-compatible zod
```

Vercel AI SDK の OpenAI 互換 provider を用いて OpenRouter へ接続する。
OpenRouter 固有のクライアントに依存しないことで、モデル / プロバイダーの差し替えを容易にする。

### 2.2 環境変数設定

`.env` に追加:

```env
# OpenRouter API Key
OPENROUTER_API_KEY=your-api-key
# 使用モデル（Gemma / Qwen / Llama へ切り替え可能）
AI_MODEL=google/gemma-3-27b-it
```

**モデル名をソースコードへ直接固定しない。** 必ず `AI_MODEL` から読み込む。
`OPENROUTER_API_KEY` が未設定の場合は Rule-based 実装を注入する。

### 2.4 実装詳細

#### Gateway interface (`domain/gateways/ai-decision.gateway.ts`)

```typescript
export interface DecisionContext {
	agent: {
		role: string;
		fatigue: number;
		sleepDebt: number;
		responsibility: number;
		riskTolerance: number;
	};
	situation: Record<string, number>;
	actions: string[];
}

export interface DecisionResult {
	action: string;
	reason: string;
	model?: string;
}

/**
 * Agent の意味的な意思決定を行う Gateway interface。
 * 提示された actions の中から 1 つを選ぶことのみを担当する。
 */
export interface AiDecisionGateway {
	decide(context: DecisionContext): Promise<DecisionResult>;
}
```

#### OpenRouter Adapter (`infrastructure/adapters/openrouter-ai-decision.adapter.ts`)

```typescript
import { createOpenAICompatible } from '@ai-sdk/openai-compatible';
import { generateObject } from 'ai';
import { z } from 'zod';
import type {
	AiDecisionGateway,
	DecisionContext,
	DecisionResult,
} from '../../domain/gateways/ai-decision.gateway';

const SYSTEM_PROMPT = `あなたはSLEEP CITYという仮想都市に住む一人の住民です。

あなたは都市全体の状態を知りません。
与えられた自分自身の状態、現在の状況、性格、職業上の責任だけを使って判断してください。

都市全体を最適化しようとしてはいけません。
現実の人間として自然な意思決定をしてください。

必ず提示されたactionsの中から1つだけ選んでください。

出力は指定されたJSON形式のみとしてください。`;

export class OpenRouterAiDecisionGateway implements AiDecisionGateway {
	private readonly provider: ReturnType<typeof createOpenAICompatible>;

	constructor(
		private readonly apiKey: string,
		private readonly model: string,
	) {
		this.provider = createOpenAICompatible({
			name: 'openrouter',
			baseURL: 'https://openrouter.ai/api/v1',
			apiKey,
		});
	}

	async decide(context: DecisionContext): Promise<DecisionResult> {
		// 提示された actions のみを許可し、自由な action 生成を禁止する
		const schema = z.object({
			action: z.enum(context.actions as [string, ...string[]]),
			reason: z.string(),
		});

		const { object } = await generateObject({
			model: this.provider(this.model),
			system: SYSTEM_PROMPT,
			schema,
			prompt: JSON.stringify({ agent: context.agent, situation: context.situation }),
		});

		return { action: object.action, reason: object.reason, model: this.model };
	}
}
```

#### Rule-based Fallback (`infrastructure/adapters/rule-based-ai-decision.adapter.ts`)

OpenRouter が停止しても Simulation 自体は完走可能にする。
Experiment Mode（大量 Batch 実行）でも既定でこの実装を使用する。

```typescript
export class RuleBasedAiDecisionGateway implements AiDecisionGateway {
	async decide(context: DecisionContext): Promise<DecisionResult> {
		const { fatigue, riskTolerance, responsibility } = context.agent;
		const deadlinePressure = context.situation.deadlinePressure ?? 0;

		if (fatigue > 85 && riskTolerance < 0.4 && context.actions.includes('rest')) {
			return { action: 'rest', reason: '疲労が限界に近く、リスクを避けたため', model: 'rule-based' };
		}

		if (responsibility > 0.8 && deadlinePressure > 0.7 && context.actions.includes('overtime')) {
			return { action: 'overtime', reason: '責任と締切圧力を優先したため', model: 'rule-based' };
		}

		return { action: context.actions[0], reason: '既定行動を継続したため', model: 'rule-based' };
	}
}
```

#### UseCase (`application/usecases/decide-agent-action.usecase.ts`)

Cache → OpenRouter → Fallback の順に解決する。
AI 呼び出しの失敗・Structured Output 形式不正はここで捕捉し、Simulation を止めない。

```typescript
export class DecideAgentActionUseCase {
	constructor(
		private readonly aiGateway: AiDecisionGateway,
		private readonly fallbackGateway: AiDecisionGateway,
		private readonly cache: DecisionCache,
	) {}

	async execute(context: DecisionContext): Promise<DecisionResult> {
		const key = DecisionContextKey.from(context); // Fatigue / Delay をビニングして正規化
		const cached = this.cache.get(key);
		if (cached !== undefined) {
			return cached;
		}

		try {
			const result = await this.aiGateway.decide(context);
			this.cache.set(key, result);
			return result;
		} catch {
			return this.fallbackGateway.decide(context);
		}
	}
}
```

Decision Cache のキーは Context をそのまま使わず、以下のように正規化（ビニング）した値から生成する。

```text
Role = Driver
Fatigue = 80〜90
Delay = 20〜30分
Responsibility = High
RiskTolerance = Medium
```

#### Composition (`presentation/composition/decision.composition.ts`)

```typescript
function createAiDecisionGateway(): AiDecisionGateway {
	const apiKey = process.env.OPENROUTER_API_KEY;
	const model = process.env.AI_MODEL;
	if (apiKey && model) {
		return new OpenRouterAiDecisionGateway(apiKey, model);
	}
	return new RuleBasedAiDecisionGateway();
}
```

#### Decision Trigger（Simulation Engine 側）

全 Agent を毎 Tick AI 推論させない。通常行動は Rule-based で処理し、
以下のような重要 Decision が発生した Tick でのみ AI を呼び出す。

| トリガー | 提示する actions |
|---|---|
| Driver の Fatigue が閾値超過 | `rest` / `continue_driving` / `ask_help` |
| 業務が終業時刻を超過 | `overtime` / `go_home` / `delegate` |
| Manager がタスク遅延を検知 | `request_overtime` / `reassign` / `accept_delay` |
| 配送が遅延 | `prioritize_delivery` / `rest` |
| 帰宅後に家事が残っている | `do_housework` / `ask_family` / `sleep` |

## 3. コスト・性能上の制約

- AI を毎 Tick 呼び出さない（Decision Trigger 方式）
- Decision Cache により類似 Context の再利用を行う
- Batch Experiment・Critical Point Explorer・Super-spreader Explorer の Stage 1 は Rule-based Mode で実行する
- Super-spreader Explorer の Stage 2（上位 10〜20 Agent）でのみ AI Decision を有効化する

## 4. テスト計画

| 対象 | 種別 | 検証内容 |
|---|---|---|
| `DecideAgentActionUseCase` | Unit | Cache ヒット時に AI を呼ばない / AI 失敗時に Fallback へ切り替わる |
| `RuleBasedAiDecisionGateway` | Unit | 各ルールの境界値（fatigue = 85, responsibility = 0.8 等） |
| `DecisionContextKey` | Unit | ビニングが期待通りのキーを生成する |
| `OpenRouterAiDecisionGateway` | Integration | Structured Output のパース / 形式不正時に例外を投げる |
| Simulation 全体 | Integration | OpenRouter を常時失敗させても Run が完走する |

## 5. 完了条件

- OpenRouter 経由で Agent が提示された actions から 1 つを選択し、reason とともに保存される

- OpenRouter 障害時も Rule-based Fallback により 300 Agent × 7 日の Run が完走する
- Agent Detail 画面で Last AI Decision・Decision Reason・使用 AI Model を確認できる
